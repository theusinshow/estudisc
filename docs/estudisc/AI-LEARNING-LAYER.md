# Bounded optional contextual assistance

[ADR 0053](../ADR/0053-contextual-ai-boundaries-and-cost-controls.md) extends the existing tutor/generation gateway. The five actions explain a published lesson/Question excerpt, give a Question hint, summarize factual mistake groups or completed sessions, and explain an actual curriculum relation. The server resolves ownership, exact source versions and availability; clients cannot supply canonical facts, owner, provider or model.

All actions are blocked during an active EXAM. Reserved Questions stay excluded even after a training unlock. Contexts omit assets/links, owner identifiers, learner code and full histories. Mistake summaries do not infer a cause; relation explanations preserve actual direction/strength and do not certify official mapping. Structured generated text is escaped and labelled as AI; it never writes mastery, retention, planner decisions, scores or publication.

Question help uses the existing conservative solution-exposure attestation before provider/cache output. No Attempt or ConceptEvidence is created by consulting AI. Later answers remain evaluated by the existing help-aware grader. An actually completed attestation is preserved and disclosed even if the provider fails. An absent provider before attestation creates no synthetic help or successful retrieval.

One existing configured provider/model is used, without stronger-model escalation or repair retries. A request has bounded context/output and a twenty-second provider timeout/cancellation path. Owned append-only StudyEvents reserve six provider calls per minute/twenty per UTC day, two pending calls and thirty total requests/minute including caches. Identical pending contexts are not called twice. Failures consume their reservation; reported usage/cost estimates retain their pricing version. No exact monetary cap is claimed.

Successful output has a one-hour cache scoped by owner, source/content hash/version, action/message, prompt policy and provider/model. Cache hits revalidate exam/access/help and do not extend the original provider result's lifetime. Reused UUIDs replay their original context/outcome; conflicting reuse fails. Prior policy reservations continue counting toward quotas. History uses readable consultation/reflection labels; owned backups retain the full immutable ledger.

`FEATURE_AI_LEARNING` gates the new endpoint/controls. The old tutor request shape shares the controlled service, preventing an alternate bypass. Authored text/hints, submissions and session summaries continue working when AI is disabled/unconfigured. The serial E2E server clears provider keys explicitly; tests make no real provider calls.
